------------------------------------------------------------
5.1 MODELO DE LOTES O TANDADAS
------------------------------------------------------------

Problema actual:
El inventario solo conserva stock agregado. No puede distinguir:
- 30 teclados comprados a $2;
- 170 teclados comprados a $2;
- otra compra posterior a $3;
- qué unidades se vendieron;
- qué costo y PVP correspondieron a cada unidad.

Crear una estructura normalizada que permita trazabilidad completa.

Tablas mínimas preferidas:

A. regla_precio
Campos mínimos:
- cod_regla_precio BIGINT identity PK
- cod_producto BIGINT nullable FK
- cod_categoria BIGINT nullable FK
- margen_porcentaje NUMERIC
- costo_operativo_porcentaje NUMERIC
- costo_fijo_unitario NUMERIC
- porcentaje_impuesto NUMERIC nullable
- prioridad INTEGER
- activo BOOLEAN
- fecha_inicio TIMESTAMPTZ nullable
- fecha_fin TIMESTAMPTZ nullable
- fecha_creacion
- fecha_actualizacion

Reglas:
- Debe existir objetivo producto, categoría o regla global.
- Prioridad: producto > categoría > global.
- No permitir márgenes negativos.
- Evitar reglas activas ambiguas con la misma prioridad.

B. lote_inventario
Campos mínimos:
- cod_lote BIGINT identity PK
- numero_lote VARCHAR unique
- cod_producto BIGINT FK
- cod_almacen BIGINT FK
- cod_proveedor BIGINT nullable FK
- cod_orden_abastecimiento_detalle BIGINT nullable FK
- cantidad_recibida INTEGER
- cantidad_disponible INTEGER
- cantidad_reservada INTEGER
- costo_unitario NUMERIC(12,4)
- margen_porcentaje_aplicado NUMERIC
- costo_operativo_aplicado NUMERIC
- porcentaje_impuesto_aplicado NUMERIC
- pvp_unitario NUMERIC(12,2)
- fecha_recepcion TIMESTAMPTZ
- fecha_vencimiento nullable
- estado: ACTIVO, AGOTADO, BLOQUEADO, ANULADO
- fecha_creacion
- fecha_actualizacion

Checks:
- cantidades no negativas;
- reservada <= disponible o definir con claridad si disponible representa físico total;
- costo y PVP positivos;
- producto y almacén obligatorios;
- un lote recibido no debe cambiar de costo histórico.

C. pedido_detalle_lote
Campos mínimos:
- cod_pedido_detalle_lote BIGINT identity PK
- cod_pedido_detalle BIGINT FK
- cod_lote BIGINT FK
- cantidad INTEGER
- costo_unitario_historico NUMERIC
- pvp_unitario_historico NUMERIC
- descuento_unitario NUMERIC
- precio_final_unitario NUMERIC
- subtotal_linea_lote NUMERIC
- fecha_asignacion
- unique o índice adecuado por detalle/lote

D. Reservas por lote
Preferencia:
- Adaptar reserva_inventario para que tenga cod_lote y cod_pedido_detalle,
  manteniendo compatibilidad con las columnas existentes.
- Cada reserva debe apuntar al lote real utilizado.
- Validar que producto y almacén coincidan con el lote.
- Crear índices para reservas activas y lotes con disponibilidad.

Aceptación:
Una compra de 40 unidades debe poder generar:
- 30 unidades desde lote con costo $2;
- 10 unidades desde lote con costo $3;
- total exacto calculado por cada lote;
- promedio solo como resumen, nunca como pérdida de trazabilidad.

5.4 REPOSICIÓN AUTOMÁTICA
------------------------------------------------------------

Problema actual:
Solo se abastece el faltante del pedido. Si existe stock exacto para vender, el
producto puede quedar en cero y no se genera reposición.

Crear:
- fn_stock_proyectado_producto_almacen(...)
- fn_cantidad_pendiente_abastecimiento(...)
- fn_generar_reposicion_automatica(p_cod_producto, p_cod_almacen)
- fn_recalcular_reposicion_producto(...)
- opcional fn_procesar_reposiciones_pendientes()

Reglas:
- Usar inventario.stock_minimo y stock_maximo.
- Stock proyectado =
  disponible real + cantidades en órdenes abiertas - reservas activas.
- Si stock proyectado <= stock_minimo, abastecer hasta stock_maximo.
- No duplicar órdenes abiertas por el mismo producto/proveedor/objetivo.
- Seleccionar proveedores activos por:
  prioridad, disponibilidad, costo, tiempo de entrega y calificación.
- Permitir dividir el abastecimiento entre varios proveedores.
- La reposición debe ejecutarse después de una venta/consumo y al recibir ajustes.
- Si ningún proveedor puede cubrir, crear alerta crítica; no inventar disponibilidad.
- "Nunca dejar de vender" debe interpretarse como reposición preventiva y uso de
  proveedores, no como promesa imposible si todos los proveedores están agotados.

Al recibir una orden:
- actualizar stock del proveedor;
- crear uno o varios lotes con el costo real de la orden;
- recalcular inventario;
- recalcular precio de exhibición;
- reservar para el pedido que esperaba proveedor;
- avanzar el estado cuando quede totalmente cubierto.
